# 실제 평가 연결과 로컬 시연

- 독자·질문: 프로젝트 작업자 / 유료 API를 최소 비용으로 검증하고 로컬 시연 근거를 어떻게 확정할까?
- 상태: 로컬 시연 범위 완료. 공개 출시·실제 참가자 파일럿은 후속. 키 값과 실제 사용자 답변은 저장소·로그·보고서에 기록하지 않음
- 기준: [Phase 5 남은 항목](../../planning/tasks.md), [reference-v1](../../evaluation/reference-v1/README.md), [로컬 실행](../2026-09-27-release-readiness/local-runbook.md)

## 완료 순서

1. 평가·후속 질문 스위치 분리, 예산 기본값 조정, 요금·크레딧 오류를 무의미하게 재시도하지 않는 계약. 자동 테스트에서 실패와 복구 확인
2. API 라이브 평가 러너: 기본 1건, 명시한 case 수·split·모델만 호출. 입력과 정답 분리. 결과에는 verdict·근거 유효성·토큰·추정 비용·latency·실패 원인만 저장
3. 새 키를 cmux 보조 터미널에 숨김 입력. OpenAI 프로젝트의 강제 지출 한도·잔액 확인 후 1건 → 소표본 → development → 고정 candidate 순으로 실행
4. 로컬 PostgreSQL 앱과 cmux 브라우저에서 답변 제출부터 평가·학습 상태·후속 흐름까지 실제 사용자 경로 검증. 결과 pane 유지
5. GPT 평가 지시문 기준선과 개선안을 동일 개발 사례에서 비교하고, 고정 후보 분할에서 false-correct·근거·schema·p95·비용 기록. 품질 Gate 실패 시 실패로 표기하고 제출 설명의 한계를 갱신
6. 시연 영상: cmux 실제 브라우저 장면을 단계별 캡처해 무음 MP4로 편집. 실시간 녹화가 아님을 명시하고 비밀정보·개인 데이터 제외

## 실패 조건

- 키가 노출되었거나 소유 프로젝트·지출 한도를 확인하지 못함: 유료 호출 중단
- 키 없음·미승인 모델·요금 오류: 원인 기록, 반복 호출 금지
- schema 위반·근거 불일치·오답 정답화: 품질 Gate 미달
- 후보 분할을 프롬프트 조정에 재사용: 독립 비교 성립하지 않음
- 브라우저 미실행·모의 결과만 확인: 실제 API E2E 완료 아님

```text
사용자 답변 → Evaluation worker → Retrieval → EvaluationPort
                                      └→ OpenAI adapter → Responses API
응답 usage·판정·근거 → Evaluation 저장 → 화면·학습 상태
          └→ 보고서·Platform 지출 확인
```
