# CrackCS 추가 확장 기능 — 초안

## 분리 기준

```text
필수 기능
문제 → 답변 → Retrieval → AI 평가 → Knowledge State → 후속 질문/추천

확장 기능
위 흐름이 완성된 뒤 학습 경험, 운영, 수익화 또는 분석을 강화하는 기능
```

확장 기능이 필요한 시점이 오면 이 문서에서 필수 명세로 이동한 후 ERD와 API를 확정한다. 아이디어 단계의 엔티티를 필수 ERD에 미리 넣지 않는다.

## 1. 학습 세션과 목표

### 기능

- 하루 또는 학습 회차 단위의 세션 관리
- 일일 문제 수와 학습 시간 목표 설정
- 목표 Topic과 목표 난이도 설정
- 학습 연속 일수와 목표 달성률 제공
- 중단한 세션 이어서 학습

### 추가 모델 후보

| 모델 | 책임 |
|---|---|
| `LEARNING_SESSION` | 학습 시작·종료 시각과 한 회차의 문제 묶음 관리 |
| `MEMBER_GOAL` | 회원별 학습 주제, 목표량, 목표 난이도 관리 |
| `DAILY_PROGRESS` | 날짜별 목표 달성량 집계 |

## 2. 추천 고도화

### 기능

- 추천 이유 상세 제공
- 추천 결과에 대한 사용자 피드백
- 망각 곡선을 고려한 복습 문제 추천
- 최근 정답률에 따른 자동 난이도 조절
- 같은 Topic의 과도한 반복 방지
- 추천 알고리즘 A/B 테스트

### 추가 모델 후보

| 모델 | 책임 |
|---|---|
| `RECOMMENDATION_HISTORY` | 어떤 상태를 근거로 어떤 문제를 추천했는지 기록 |
| `RECOMMENDATION_FEEDBACK` | 추천이 유용했는지에 대한 회원 피드백 저장 |
| `ALGORITHM_EXPERIMENT` | 추천 알고리즘 버전과 실험군 관리 |

추천 이력이 없더라도 현재 Knowledge State를 이용해 다음 문제를 고를 수 있으므로 필수 ERD에는 포함하지 않는다.

## 3. 문제 유형과 자동 생성

### 기능

- 객관식 문제
- 복수 선택 문제
- 코드 작성 및 실행 문제
- 빈칸 채우기 문제
- AI 문제 자동 생성
- 자동 생성 문제 검수 및 전체 공개
- 사용자의 서술형 문제 제안
- 사용자 제안 문제의 검수 및 공개
- 문제별 제한 시간

### 추가 모델 후보

| 모델 | 책임 |
|---|---|
| `QUESTION_OPTION` | 객관식 선택지와 정답 여부 관리 |
| `CODE_TEST_CASE` | 코드 문제의 입력, 예상 출력, 공개 여부 관리 |
| `QUESTION_GENERATION_HISTORY` | 생성 모델, 프롬프트, 근거 문서와 생성 결과 추적 |
| `QUESTION_REVIEW` | 자동 생성 문제의 검수 상태와 검수자 기록 |
| `QUESTION_SUBMISSION` | 사용자 문제 제안과 검수 상태 관리 |

현재 필수 Question은 관리자가 등록·검수한 서술형과 후속 질문만 다룬다. 문제 공급 방식의 선택 이유는 [콘텐츠·AI 운영 정책](./content-and-ai-policy.md)을 따른다.

## 4. 평가 고도화

### 기능

- 평가 결과 이의 제기
- 관리자 또는 전문가의 수동 재평가
- 여러 AI 모델 평가 결과 비교
- 평가 기준 버전별 품질 비교
- 답변 표현력과 면접 전달력 평가
- 유사 모범 답안 비교

### 추가 모델 후보

| 모델 | 책임 |
|---|---|
| `EVALUATION_APPEAL` | 회원의 이의 제기 내용과 처리 상태 관리 |
| `HUMAN_REVIEW` | 전문가 점수, 피드백과 AI 평가 수정 내역 관리 |
| `MODEL_EVALUATION_SAMPLE` | 동일 답변에 대한 여러 모델의 실험 결과 보관 |

필수 흐름은 승인 지식을 근거로 한 AI 평가 한 건만 제공한다.

## 5. 콘텐츠 운영 고도화

### 기능

- 문서 버전 간 차이 비교
- 외부 문서 저장소 자동 동기화
- Topic과 Concept 일괄 등록
- 오래되거나 충돌하는 지식 탐지
- 복수 관리자 승인 절차
- 검수 작업 배정과 마감일 관리

### 추가 모델 후보

| 모델 | 책임 |
|---|---|
| `DOCUMENT_REVISION` | 문서 버전별 원문과 변경 사유 보관 |
| `CONTENT_REVIEW` | 콘텐츠 승인 상태와 검수자 기록 |
| `DOCUMENT_SYNC_JOB` | 외부 문서 동기화 상태와 실패 원인 관리 |

필수 기능에는 관리자 페이지의 기본 등록·수정·검수·공개 기능이 포함된다. 이 절은 대량 운영과 복수 검수자를 위한 고급 기능만 다룬다.

## 6. 학습 편의 기능

### 기능

- 작성 중 답변 임시 저장
- 문제 북마크
- 개인 학습 노트
- 취약 개념 복습 알림
- 이메일 또는 푸시 알림
- 학습 데이터 내보내기
- 다크 모드와 접근성 설정

### 추가 모델 후보

| 모델 | 책임 |
|---|---|
| `ANSWER_DRAFT` | 제출 전 답변 임시 저장 |
| `QUESTION_BOOKMARK` | 회원별 문제 즐겨찾기 관리 |
| `LEARNING_NOTE` | 문제 또는 Concept에 연결된 개인 노트 관리 |
| `NOTIFICATION_SETTING` | 회원별 알림 수단과 수신 조건 관리 |

## 7. 소셜 기능

### 기능

- 사용자 간 학습 랭킹
- 다른 사용자의 공개 답변 조회
- 답변 피드백과 댓글
- 스터디 그룹
- 문제 공유

### 추가 모델 후보

| 모델 | 책임 |
|---|---|
| `STUDY_GROUP` | 스터디 정보와 구성원 관리 |
| `ANSWER_COMMENT` | 공개 답변에 대한 댓글 관리 |
| `SHARED_QUESTION` | 문제 공유 범위와 링크 관리 |
| `RANKING_SNAPSHOT` | 기간별 학습 순위 집계 |

소셜 기능을 도입하려면 답변 공개 범위와 개인정보 정책을 먼저 확정해야 한다.

## 8. 인증 방식 확장

### 기능

- 이메일 소유 확인
- 비밀번호 재설정
- Google, GitHub 등 소셜 로그인
- 기존 LOCAL 계정과 소셜 계정 연결
- 2단계 인증

### 추가 모델 후보

| 모델 | 책임 |
|---|---|
| `EMAIL_VERIFICATION` | 이메일 인증 토큰과 만료 시각 관리 |
| `PASSWORD_RESET_TOKEN` | 일회용 비밀번호 재설정 요청 관리 |
| `SECOND_FACTOR` | 회원별 2단계 인증 수단 관리 |

필수 ERD의 `AUTH_ACCOUNT.provider` 구조를 이용하면 Member를 바꾸지 않고 인증 수단을 추가할 수 있다.

## 9. 결제와 구독 — 후순위

### 기능

- 무료·유료 플랜
- 월간 및 연간 구독
- AI 평가 사용량 제한
- 결제 내역과 환불
- 플랜별 기능 접근 제어

### 추가 모델 후보

| 모델 | 책임 |
|---|---|
| `SUBSCRIPTION` | 회원의 플랜과 구독 상태 관리 |
| `PAYMENT` | 결제 승인, 취소와 환불 이력 관리 |
| `USAGE_QUOTA` | 기간별 AI 평가 사용량과 한도 관리 |

비즈니스 모델 도입은 후순위다. 결제는 학습 효과, 사용자 유지율과 AI 평가의 단위 비용이 검증된 이후에만 설계한다.

## 10. 도입 우선순위 제안

| 단계 | 기능군 | 도입 조건 |
|---|---|---|
| 1차 확장 | 학습 세션, 목표, 임시 저장 | 필수 학습 루프가 안정적으로 동작함 |
| 2차 확장 | 추천 이력, 복습 주기, 자동 난이도 | 충분한 학습 이력이 축적됨 |
| 3차 확장 | AI 문제 초안, 사용자 문제 제안, 콘텐츠 운영 고도화 | 문서 검수 기준과 평가 품질 기준이 확정됨 |
| 4차 확장 | 소셜 | 답변 공개와 개인정보 정책이 확정됨 |
| 최종 검토 | 결제와 구독 | 사용자 유지율, 학습 효과와 평가 원가가 검증됨 |
