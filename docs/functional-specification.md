# CrackCS 필수 기능 명세서 — 초안

## 확정된 운영 방향

| 항목 | 결정 |
|---|---|
| 초기 문제 형식 | 모든 문제는 서술형 주관식으로 제공한다. |
| 초기 학습 범위 | CS 기초와 Java·Spring·JPA 중심의 백엔드 기본 지식 |
| 회원 인증 | 이메일과 비밀번호로 회원가입·로그인 |
| 관리자 기능 | 초기 운영부터 관리자 페이지를 필수로 제공 |
| 문제 공급 | 관리자가 검수한 문제 은행으로 시작 |
| 평가 기준 | 세부 표현력보다 문제의 핵심을 맞혔는지를 우선 판정 |
| 난이도 | 관리자가 문제 등록 시 지정하고 자동 난이도 조절은 사용하지 않음 |
| 코드 문제 | 필수 범위에서 제외하고 추후 확장 |
| 비즈니스 모델 | 학습 가치 검증 이후로 연기 |

문제 공급, AI 모델과 지식 문서 정책의 선택 이유는 [콘텐츠·AI 운영 정책](./content-and-ai-policy.md)에서 다룬다.

초기 기술 문서의 권장 기준 버전은 현재 프로젝트 설정과 안정 문서를 기준으로 한다.

| 기술 | 초기 기준 |
|---|---|
| Java | Java 21 |
| Spring Boot | 4.1.x |
| Spring Framework | 7.0.x |
| JPA | Jakarta Persistence 3.2 |

## 기능 목록

### 회원 기능

- 이메일과 비밀번호를 이용한 회원 등록
- 이메일과 비밀번호를 이용한 로그인
- 로그아웃
- 회원 조회
- 회원별 학습 현황 조회
- 회원별 문제 풀이 이력 조회

### 관리자 기능

- 관리자 페이지 접근
- 회원 조회 및 상태 관리
- CS 주제와 개념 등록·수정·조회
- 지식 문서 등록·수정·검수·공개·폐기
- 서술형 문제 등록·수정·검수·공개·폐기
- AI 평가 실패 내역 조회

### CS 지식 기능

- CS 주제 등록
- CS 개념 등록
- 지식 문서 등록
- 지식 문서 조회
- 지식 문서를 검색 가능한 단위로 분할
- 문제 및 답변과 관련된 지식 검색(Retrieval)

초기 운영 주제는 다음 두 그룹으로 구성한다.

```text
CS 기초
 ├─ 자료구조·알고리즘
 ├─ 운영체제
 ├─ 네트워크
 ├─ 데이터베이스
 └─ 컴퓨터 구조

백엔드 기본
 ├─ Java
 ├─ Spring / Spring Boot
 └─ JPA / Jakarta Persistence
```

### 문제 기능

- 서술형 문제 등록
- 문제 수정
- 문제 조회
- 문제에 평가 대상 개념 지정
- 관리자의 문제 난이도 지정
- 회원의 지식 상태에 따른 다음 문제 추천

### 문제 풀이 기능

- 문제 답변 제출
- 제출한 답변 조회
- 동일 문제 다시 답변
- 답변별 평가 결과 조회

### AI 평가 기능

- 관련 CS 지식을 근거로 답변 평가
- 답변의 정오 판정
- 정오 판정으로부터 단순 점수 산정
- 개념별 이해 여부 평가
- 잘 설명한 내용 제공
- 부족하거나 잘못 이해한 내용 제공
- 평가에 사용한 지식 문서 제공

초기 평가의 우선순위는 다음과 같다.

```text
1. 문제에서 요구한 핵심 개념을 맞혔는가?
2. 핵심 개념을 반대로 이해한 오개념이 있는가?
3. 필수 개념 중 일부만 설명했는가?
4. 문장 표현과 설명의 완성도는 어떠한가?
```

판정은 `CORRECT`, `PARTIALLY_CORRECT`, `INCORRECT`, `NEEDS_REVIEW`로 구분한다.

- `CORRECT`: 필수 개념을 맞게 설명하고 치명적인 오개념이 없음
- `PARTIALLY_CORRECT`: 핵심 방향은 맞지만 필수 개념 일부가 누락됨
- `INCORRECT`: 핵심 개념이 틀렸거나 질문에 답하지 못함
- `NEEDS_REVIEW`: 검색 근거가 부족하거나 AI 판정을 신뢰하기 어려움

초기 점수는 정오 판정을 수치화한 값으로만 사용한다.

| 판정 | 초기 점수 |
|---|---:|
| CORRECT | 100 |
| PARTIALLY_CORRECT | 50 |
| INCORRECT | 0 |
| NEEDS_REVIEW | 미반영 |

### 개인 Knowledge State 기능

- 회원·개념별 이해 상태 저장
- 평가 결과에 따른 이해 상태 갱신
- 취약 개념 조회
- 주제별 이해도 조회

### 후속 질문 기능

- 답변의 부족한 개념을 확인하는 후속 질문 생성
- 답변을 잘한 경우 심화 후속 질문 생성
- 후속 질문 답변
- 후속 답변 재평가

## 기타 요구사항

- 회원의 비밀번호 원문을 저장하지 않고 안전한 단방향 해시만 저장한다.
- 일반 회원과 관리자의 권한을 구분한다.
- CS 지식은 `주제 > 개념` 구조로 구분할 수 있다.
- 하나의 주제에는 여러 개념이 포함된다.
- 하나의 문제는 여러 개념을 평가할 수 있다.
- 문제마다 평가할 개념과 중요도를 지정할 수 있다.
- 모든 문제는 서술형이며 하나 이상의 필수 Concept을 가져야 한다.
- 문제 난이도는 `BASIC`, `INTERMEDIATE`, `ADVANCED` 중 관리자가 지정한다.
- AI는 등록된 CS 지식 문서를 근거로 답변을 평가해야 한다.
- 하나의 답변에는 하나의 종합 평가가 생성된다.
- 종합 평가는 여러 개념별 평가 결과를 포함한다.
- 개인 Knowledge State는 주제 점수가 아니라 회원·개념 단위로 관리한다.
- 아직 평가하지 않은 개념과 낮은 점수를 받은 개념을 구분해야 한다.
- 답변을 다시 제출하더라도 이전 답변과 평가 이력은 보존한다.
- 후속 질문은 어떤 답변으로부터 생성되었는지 추적할 수 있어야 한다.
- 다음 문제는 미평가 개념 또는 취약 개념을 우선하여 추천한다.
- 평가에 실패한 답변은 Knowledge State에 반영하지 않는다.

## 핵심 흐름

```text
회원
 │
 ▼
문제 조회/추천
 │
 ▼
답변 제출
 │
 ├──────────────▶ 관련 CS 지식 검색
 │                         │
 ▼                         ▼
                    AI 답변 평가
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
       개념별 취약점 분석       평가 결과 제공
             │
             ▼
      개인 Knowledge State 갱신
             │
       ┌─────┴─────┐
       ▼           ▼
  후속 질문     다음 문제 추천
       │
       └── 답변 제출/평가 반복
```

관리자 콘텐츠 흐름은 학습 흐름 앞에서 평가 근거와 문제 품질을 보장한다.

```text
관리자 로그인
    │
    ├─ Topic / Concept 등록
    ├─ KnowledgeDocument 등록·검수
    └─ 서술형 Question + 필수 Concept 등록·검수
                         │
                         ▼
                     PUBLISHED
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
       Retrieval 근거로 사용       사용자에게 문제 제공
```

## 구현 전 세부 결정 사항

- 로그인 상태를 서버 세션과 토큰 중 어떤 방식으로 유지할지
- `PARTIALLY_CORRECT`를 판정하는 필수 Concept 충족 비율
- AI 생성 문제를 시스템 기능으로 도입할 시점

도메인 모델과 테이블 구조는 [필수 도메인 모델 및 테이블 설계](./domain-model-and-erd.md)를 따른다.

핵심 학습 루프 없이도 독립적으로 추가할 수 있는 기능은 [추가 확장 기능](./extension-features.md)에서 별도로 관리한다.
